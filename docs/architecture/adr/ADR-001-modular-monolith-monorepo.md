# ADR-001: انتخاب مونولیت ماژولار در مونوریپو (Modular Monolith in Monorepo)

## وضعیت
تصویب‌شده (Accepted) — مهر ۱۴۰۵ / اکتبر 2026

## زمینه و چالش
تجربه سه نسل سیستم‌های تجاری (Medusa در `site-shop`، سیستم ۴۴ ماژول FastAPI در `site`، و `itrip-platform`) نشان داد که:
1. استفاده از پلتفرم‌های سفت و قفل‌شده مانند Medusa انعطاف‌پذیری لازم برای چندمستأجری عمیق، بومی‌سازی مالی و ERP داخلی را با محدودیت شدید مواجه می‌کند.
2. رفتن زودهنگام به سمت میکروسرویس‌ها بدون مرزهای باثبات دامنه، پیچیدگی‌های عظیم در شبکه، توزیع تراکنش‌ها (Distributed Transactions) و شکست‌های عملیاتی ایجاد می‌کند.
3. در عین حال، مرزهای تمیز دامنه و جداسازی پکیج‌های مستقل برای مقیاس‌پذیری و تست‌پذیری حیاتی هستند.

## تصمیم
استفاده از معماری **مونولیت ماژولار (Modular Monolith)** داخل یک **مونوریپو (pnpm + Turborepo)** با پشته فناوری تماماً TypeScript:
- **apps/api**: هسته ماژولار بر پایه NestJS 11 و Prisma ORM با درایور PostgreSQL.
- **apps/storefront**: ویترین فروشگاهی سمت کاربر بر پایه Next.js 16 (App Router و React 19 Server Components).
- **apps/admin**: پنل مدیریت و ERP عملیاتی بر پایه Next.js 16.
- **apps/worker**: سرویس پس‌زمینه مستقل برای مدیریت صف رویدادها (Outbox) و کارهای زمان‌بندی‌شده.
- **packages/*** : پکیج‌های مشترک و مستقل دامنه، مالی، امنیت، درگاه‌ها، بومی‌سازی و UI.

## پیامدها
- به اشتراک‌گذاری تایپ‌های قوی (Type Sharing) سرتاسری بین بک‌اند و فرانت‌اند بدون نیاز به تبدیل دستی.
- تراکنش‌های اتمیک در دیتابیس مشترک با حفظ استقلال کامل ماژول‌ها.
- امکان استخراج آسان هر ماژول به یک میکروسرویس مستقل در فازهای بلوغ و نیاز به مقیاس مستقل.
